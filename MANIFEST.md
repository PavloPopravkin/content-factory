## Что это / для кого
Open-source контент-фабрика для фондов и компаний: люди скидывают фото, видео, голосовые; AI по инструкциям
организации собирает посты, сторис, рилсы и публикует во все каналы. Первые пользователи: благотворительный фонд и компания с десятками страниц.

## Инварианты
- План публикаций владеет только фабрика; Postiz хранит её посты как DRAFT-витрину и публикует только после продвижения фабрикой.
- Шабат - свойство платформы: ни один тенант его не выключает, guard в форке Postiz fail-closed.
- `tenant_id` в каждой сущности; ключи соцсетей только у publisher; AI-куратор без ключей, в песочнице.
- Журнал доставки до внешнего вызова; потерянный ответ = unknown, без слепого повтора.
- Факты в текстах только с происхождением из присланного или прошлых постов.

## Правила проекта (слово Pavel'я, клиента, команды; действует всегда)

### Публикации: что и когда
- Перед каждым HTTP-запросом публикации проверять шабат, апрув и лимиты, 2026-10-25, DECISIONS.md, "Детерминированное ядро и запрет слепой повторной доставки" и "Postiz исполнителем за своим сервисом, план владеет фабрика".
- Попытки учитывать по фактическому времени, чтобы очередь не обходила лимиты и интервалы; просроченные слоты отмечать `missed`, 2026-10-25, DECISIONS.md, "Детерминированное ядро и запрет слепой повторной доставки" и "Повтор только после явного отказа без публичного эффекта".
- Апрув привязывать к хешу контента и каналов; для апрува точных байтов нужны неизменяемые derivatives, поскольку URL фиксирует только адрес и метаданные, 2026-10-25, DECISIONS.md, "Повтор только после явного отказа без публичного эффекта".
- Автоматический повтор допустим только после явного отказа без публичного эффекта; публичную частичную отправку автоматически не повторять, 2026-10-25, DECISIONS.md, "Повтор только после явного отказа без публичного эффекта".
- Сверка доставки работает только на чтение и не публикует готовый IG container; `unknown` без внешнего ID требует проверки оператором, 2026-10-25, DECISIONS.md, "Детерминированное ядро и запрет слепой повторной доставки".

### Код: стиль и договорённости
- Изоляцию организаций в SQLite закреплять составными внешними ключами с tenant, 2026-10-25, DECISIONS.md, "Детерминированное ядро и запрет слепой повторной доставки".
- Держать уникальный delivery fence на пару slot × channel; `deferred` и `next_attempt_at` сохраняют тот же fence, 2026-10-25, DECISIONS.md, "Повтор только после явного отказа без публичного эффекта".
- Сохранять каждый известный внешний ID по мере отправки, не откладывая запись до завершения альбома, 2026-10-25, DECISIONS.md, "Детерминированное ядро и запрет слепой повторной доставки".
- Для Postiz использовать постоянный token bucket по URL и ключу организации, 2026-10-25, DECISIONS.md, "Повтор только после явного отказа без публичного эффекта".
- Tick защищать file lock; короткие SQLite-транзакции должны позволять оператору отменять следующие HTTP-запросы, 2026-10-25, DECISIONS.md, "Детерминированное ядро и запрет слепой повторной доставки" и "Повтор только после явного отказа без публичного эффекта".

### Статусы и договорённости
- Перед продом проверить форматы, media limits и фактические внешние ID на отдельных тестовых каналах; реальные staging smoke-тесты адаптеров и прав приложений пока не выполнялись, дата не указана, DEBT.md, "Открыто после phase 1".
- Учитывать, что Postiz delete не удаляет опубликованный объект в соцсети и возвращает `UnsupportedOperation`, дата не указана, DEBT.md, "Открыто после phase 1".

## Целевая архитектура
- Postiz как исполнитель за адаптером `Publisher`, прямые адаптеры Telegram и Meta. Критерий: smoke всех типов постов.
- Второй tenant проходит полный цикл на чистой установке по README. Критерий: без личного окружения автора.

## Non-goals
- Свой OAuth и публикация всех сетей с нуля.
- Модификация Postiz вне патч-набора `FACTORY-PATCH` (потолок 10 точек касания upstream).
- SPA-админка; хватит FastAPI + htmx.

## Стек
Python 3.12, FastAPI, SQLite WAL, ffmpeg/Pillow, Whisper, headless Claude/Codex, Postiz API, Docker compose.
