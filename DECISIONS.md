## 2026-10-25 · Детерминированное ядро и запрет слепой повторной доставки
- **Решение:** SQLite WAL со составными tenant FK, versioned approval, уникальным fence на slot × channel и checkpoint каждого известного внешнего ID; tick держит file lock и проверяет policy перед каждым HTTP-запросом.
- **Отвергли:** повторный POST после timeout, отдельный delivery для каждой версии уже отправленного слота, журнал только после завершения альбома и автоматическую публикацию готового IG container из reconciliation.
- **Почему:** потерянный ответ не доказывает отсутствие публикации, частичная отправка должна оставаться видимой; read-only reconciliation не создаёт дубликаты. Попытки учитываются по фактическому времени, чтобы backlog не обходил лимиты и интервалы.
- **Цель манифеста:** фабрика владеет планом, tenant isolation, outbox до вызова, чистый цикл второго tenant.
- **Граница:** accepted job внешнего сервиса может закончиться после blackout; unknown без внешнего ID требует проверки оператором.
- **Статус:** реализовано в phase1-core по задаче Pavel 25.10.2026.

## 2026-10-25 · Postiz исполнителем за своим сервисом, план владеет фабрика
- **Решение:** публикация через адаптер `Publisher`: Postiz v2.25.3+ для большинства сетей, прямые Telegram и Meta (FB Reels, Stories). Фабрика держит план и в момент слота вызывает "опубликовать сейчас" после проверки шабата, апрува и лимитов.
- **Отвергли:** (а) свой OAuth и публикация всех сетей; (б) только Postiz без сервиса (нет приёма, AI, политики, ролей, идемпотентности); (в) TryPost основным (молод, один ключ на workspace); (г) отложенные посты внутри Postiz (Temporal спит мимо шабата и апрува, ревью Codex).
- **Почему:** research/oss-landscape.md, research/postiz-backend.md, research/critique.md. Pavel 25.10: "можем использовать эту штуку, допилить".
- **Статус:** ждёт ок Pavel'я.
