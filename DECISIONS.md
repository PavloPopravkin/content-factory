## 2026-11-05 · Одна платформа: фабрика + тонкий форк Postiz, для служения, благотворительности и коммерции
- **Решение:** content-factory (Python, MIT) - ядро для тенантов `ministry`, `charity`, `commerce`: план, апрув по хешу с актором, шабат (свойство платформы, тенант не выключает), факты, журнал доставки, Telegram-бот с диалогом, куратор. Postiz-форк `postiz-cf` (AGPL) - админка и исполнитель: посты фабрики лежат в Postiz как DRAFT, в слот фабрика их продвигает; патчи помечены `FACTORY-PATCH`, потолок 10 точек касания upstream, fail-closed guard перед каждой внешней мутацией (UI, Public API, MCP, агент), экраны фабрики открываются из меню Postiz (iframe + JWT). Legacy-движки `server-root/scripts/autopost` и `yourhelp/autopost` выводятся по одному каналу после shadow. План: `research/2026-11-05/PLAN-PLATFORM.md`.
- **Отвергли:** свой движок без Postiz (`server-root/DECISIONS.md` 2026-11-04, заменена); sidecar без форка (ручной `now` в UI Postiz обходит шабат и апрув); глубокий форк с переписыванием ядра на TS (обнуляет доказательства шабата, вечный rebase горячих файлов); план в БД Postiz через новую activity; двустороннюю синхронизацию плана; нативный апрув Postiz (его нет, issue #1758 закрыт not_planned); диалоговый бот внутри Postiz (Telegram-провайдер только публикует).
- **Почему:** Pavel 05.11: "одна большая система... через Postiz... чтобы можно было подключать Telegram-бота... админка тоже в Postiz", потом продавать. Рой 05.11: 6 разведчиков, 3 архитектуры, 3 судьи (тонкий форк 81/81/78), ревью Codex (24 из 25 находок подтверждены и внесены).
- **Цель манифеста:** "Postiz как исполнитель за адаптером Publisher" и "второй tenant по README на чистой установке".
- **Граница:** форк публичный под AGPL §13 (исходники для пользователей сети), фабрика отдельно под MIT. Прод-шаги (бэкап Postiz, forward_auth, GBP OAuth, выкат образа) только с ок Pavel'я.

## 2026-10-25 · Повтор только после явного отказа без публичного эффекта
- **Решение:** `deferred` и `next_attempt_at` сохраняют тот же delivery fence; Postiz получает постоянный token bucket по URL и ключу организации, апрув привязан к хешу контента и каналов, просроченные слоты отмечаются `missed`.
- **Отвергли:** удаление fence ради повтора, повтор после потерянного ответа и общий file lock для отмены во время tick.
- **Почему:** явный rate limit допускает новую попытку без дубля, а public parts и неоднозначные ответы требуют сверки; короткие SQLite-транзакции позволяют оператору отменить следующие HTTP-запросы.
- **Цель манифеста:** outbox до вызова, единственный владелец плана и воспроизводимая установка второго tenant.
- **Граница:** URL фиксирует адрес и метаданные, для точного апрува байтов нужны неизменяемые derivatives; публичная частичная отправка автоматически не повторяется.
- **Статус:** исправления round 2, миграция 002.

## 2026-10-25 · Детерминированное ядро и запрет слепой повторной доставки
- **Решение:** SQLite WAL со составными tenant FK, versioned approval, уникальным fence на slot × channel и checkpoint каждого известного внешнего ID; tick держит file lock и проверяет policy перед каждым HTTP-запросом.
- **Отвергли:** повторный POST после timeout, отдельный delivery для каждой версии уже отправленного слота, журнал только после завершения альбома и автоматическую публикацию готового IG container из reconciliation.
- **Почему:** потерянный ответ не доказывает отсутствие публикации, частичная отправка должна оставаться видимой; read-only reconciliation не создаёт дубликаты. Попытки учитываются по фактическому времени, чтобы backlog не обходил лимиты и интервалы.
- **Цель манифеста:** фабрика владеет планом, tenant isolation, outbox до вызова, чистый цикл второго tenant.
- **Граница:** accepted job внешнего сервиса может закончиться после blackout; unknown без внешнего ID требует проверки оператором.
- **Статус:** реализовано в phase1-core по задаче Pavel 25.10.2026.

## 2026-10-25 · Postiz исполнителем за своим сервисом, план владеет фабрика
- **Решение:** публикация через адаптер `Publisher`: Postiz v2.25.3+ для большинства сетей, прямые Telegram и Meta (FB Reels, Stories). Фабрика держит план и в момент слота вызывает "опубликовать сейчас" после проверки шабата, апрува и лимитов.
- **Отвергли:** (а) свой OAuth и публикация всех сетей; (б) только Postiz без сервиса (нет приёма, AI, политики, ролей, идемпотентности); (в) TryPost основным (молод, один ключ на workspace); (г) отложенные посты внутри Postiz (Temporal спит мимо шабата и апрува, ревью Codex).
- **Почему:** research/oss-landscape.md, research/postiz-backend.md, research/critique.md. Pavel 25.10: "можем использовать эту штуку, допилить".
- **Статус:** ждёт ок Pavel'я.
